# 新工作台准入与恢复规范
版本：1.0  
日期：2026-10-15（UTC+08:00）  
维护角色：项目协调负责人；每个工作台指定唯一执行负责人和回收负责人。  
范围：新建、迁移、替换及用途发生变化的工作台。此文件是通用操作要求，不包含个人资料、客户资料或项目私有研究。

## 1. 先确认用途，再验最小能力
建立工作台前列明用途、交付物和必需能力；先用无敏感样例验证，通过后才导入全案学习资料并分配依赖这些能力的正式任务。环境显示“运行中”、助手文字回复正常、生成了路径或链接，都不等于完整通过。
记录实际会话/任务、执行环境、仓库、分支和可用工具的身份及相互对应关系；仅记录不含凭据的标识，私有身份细节放在获准的私有记录中。

### 工程类
按任务需要验证命令执行、仓库读取和隔离写入、依赖及构建/测试工具、容量和网络、必要预览能力、版本提交与远端读取；无关能力不强制测试。生产、部署、DNS、付费和权限变更仍受原授权限制。
### 研究、文档、行政类
按任务需要验证来源检索和引用、附件完整读取、中文正文/表格/图像处理、所需 PDF/DOCX/ZIP 等格式生成及可读性、实际下载交付、仓库记录与恢复。未来社媒内容工作按用途补测，不因该用途自动授权发布。无需为文档任务强制搭建网站或工程构建链。

## 2. 无敏感端到端验收
1. 在隔离测试目录写入唯一标记的小文件，读取并核对；若任务依赖命令执行，运行安全命令并记录实际返回值。
2. 生成用途所需的最小样例文件。PDF 检查中文、页数及可读性；ZIP 检查目录和可解压性。
3. 通过目标用户实际可用的交付渠道发送样例，验证交付对象确实可取得并打开文件。不能仅凭本地文件存在、链接显示、助手自述或服务接收消息判定通过。无法验证接收端下载时标为“待验”，不得宣称已修复。
4. 将无敏感规则或测试记录保存到授权仓库的隔离分支，记录提交 SHA；从远端指定提交重新读取并核对内容。本地 commit、工作目录或临时环境路径不能替代远端持久保存。
5. 在后续独立轮次从远端入口恢复：读到任务进度、最近决定、未完成事项和证据，正确复述下一步，记录证据。不得仅靠原对话上下文自称恢复成功。
6. 核对测试未泄露凭据或私有资料，指定测试文件回收负责人、范围和时间。先保留必要验收证据；删除仍遵守授权与可恢复性要求。

## 3. 判定和复用
每项记录“通过 / 未通过 / 待验证 / 不适用”，不适用项写明理由。记录日期、用途、环境/工具版本或可识别配置、测试输入、结果、证据、限制、责任人和下一步。
必需项未通过或待验证时，不导入全案、不派发依赖该能力的正式任务；经确认不依赖该能力的独立工作可继续。不得把待验写成通过。
相同用途且配置未变化时引用既有有效证据，只补测差异和时效敏感项，避免每次重复全套测试。环境、工具、交付渠道、访问范围、用途发生实质变化，或出现相应故障时，重验受影响能力。日期不是永久有效保证，须结合当前状态核实。

## 4. 持久记录与最小恢复包
重要决定和进度随工作增量更新至授权的持久记录；公开仓库只存通用无敏感规范。私有原稿、客户信息、研究细节、聊天内容和凭据不得为方便恢复而上传公开仓库。
恢复包至少包含：资料索引及访问位置、已确认决定、实际版本/提交、尚未安全保存的修改清单、交付及验收证据、失败原因、当前审核阶段、依赖、唯一负责人和下一步。无法访问的文件明确标注“未保存/未核实”，不得假称已保全。
优先有界修复。确需替换时，新台先通过最低准入，再接收恢复包并核对承接；旧台保留证据与可恢复成果，避免两个负责人重复写入。明确接替、归档和测试资源回收责任，不盲目删除线程或终止可保存运行。

## 5. 协作扩展与边界
预留分支、责任范围、交接记录和审核分离的协作方式；目前单工作台无需预建多个智能体。Git worktree 可隔离同一仓库的工作目录，但不等于智能体调度、共享记忆、云端容量扩容或自动交接；是否可用必须按实际环境验证。
准入通过仅证明记录条件下的能力，不保证永不故障。故障发生后依据真实错误证据处理；正常结束、等待审批、业务缺陷、短暂无消息不能自动判为宕机。恢复不得降低业务验收门。

## 6. 最小验收记录格式
- 工作台用途与必需交付物：
- 实际任务/环境/工具/仓库/分支对应：
- 检查日期及配置：
- 各项结果、证据和限制：
- 远端提交与远端内容读回：
- 接收端下载、打开验证：
- 跨轮恢复验证：
- 尚未通过项及不受影响的可做工作：
- 唯一负责人、恢复包位置、回收负责人和下一步：

本规范的发布不代表任何现有工作台已通过上述验收；验收结论须另附实际证据。
